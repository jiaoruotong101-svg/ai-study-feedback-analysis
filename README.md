# 🎓 AI 助教也要交作业

### 从 8.2 万条用户评论中，寻找 AI 学习助手的体验问题

平时是 AI 帮学生看题，这次换我们看看：**用户给这些“AI 助教”留下了什么评语？**

这是一个大数据课程设计项目。它尝试用程序从评论中找出具体问题和改进需求，再把反馈分门别类，帮助人们更快找到值得进一步核查的线索。

**公开评论 → 数据清洗 → 反馈识别 → 问题分类 → 人工核验**

## 💬 评论区里，藏着什么？

“太差了”和“解题步骤出错了”，都可能伴随一星评分，但能提供的信息不同：前者表达不满，后者指出了可以跟进的问题。好评里也可能包含改进建议。

本项目关注两个问题：**这条评论有没有具体反馈？如果有，它在说哪方面的问题？**

下面是中文示意，用来解释分类思路，**不是数据原文，也不是模型实际预测展示**。

| 评论示意 | 有没有具体反馈？ | 涉及什么？ |
| --- | --- | --- |
| “很好用！” | 无 | 泛泛好评 |
| “太差了。” | 无 | 泛泛差评，尚未说明具体问题 |
| “答案有了，但解题步骤是错的。” | 有 | 回答与任务完成 |
| “买了会员还是限制提问。” | 有 | 收费与权益 |
| “上传图片就闪退，而且广告挡住按钮。” | 有 | 运行体验、界面与广告 |
| “整体挺好，希望能支持更多学科。” | 有 | 回答与任务完成方面的需求 |

“无具体反馈”不等于评论没有价值，只表示它没有提供本项目要识别的具体问题或改进需求。一条评论可以同时涉及多个类别。

## 🔎 我们给谁做“体检”？

研究使用 GenAI-EdSent 公开数据中的 Google Play 评论，聚焦六款学习／作业助手。

| 应用 | 清洗后纳入研究范围的评论数 |
| --- | ---: |
| Gauth | 49,570 |
| Question.AI | 16,100 |
| Answer.AI | 6,814 |
| Nerd AI | 5,694 |
| StudyX | 2,437 |
| Homework AI | 1,389 |
| **合计** | **82,004** |

选择它们，是因为学习与作业场景相近，便于用同一套问题分类分析，也能利用现有数据开展课程实验。这不是“六大最佳产品”榜单，更不代表整个 AI 教育市场。Gauth 的评论约占六成，整体统计尤其需要留意这种数量差异。

从原始数据到实验，各个数字的含义如下：

| 阶段 | 数量 | 用来做什么 |
| --- | ---: | --- |
| 原始数据 | 480,831 条／22 个应用 | 核查数据来源、质量和研究范围 |
| 清洗后候选数据 | 158,371 条 | 按时间、文本长度和应用内去重规则筛选 |
| 六应用研究子集 | 82,004 条 | 本项目的评论研究范围，并非全部用于训练 |
| 实际训练集 | 1,721 条 | 让模型从已标注例子中学习 |
| 开发集 | 347 条 | 检查模型表现，与训练集分开 |
| 人工测试样本 | 180 条 | 模型冻结后评测，其中 178 条可计分 |

原始数据实际时间范围为 **2013-12-16 至 2025-08-13**；清洗候选限定为 2023 年起的评论。这份数据不能代表产品今天的表现。

## ⚙️ 程序怎么“读懂”评论？

采用 **TF-IDF + 逻辑回归**，是一套普通电脑 CPU 就能运行的轻量文本分类方法。

1. **先给例子。** 使用带有“是否有反馈、属于什么类别”标签的评论训练。训练和开发标签来自 AI 辅助标注，可能存在标注错误。
2. **把文字变成数字。** TF-IDF 提取单词和相邻双词组合，为每条原文评论制作一张“用词特征表”。词表仅从训练集学习。
3. **学习判断规律。** 逻辑回归学习不同用词特征与标签的关系，不是手写“出现某个词就归某类”的规则。
4. **分两步输出。** 一个分类器判断有没有具体反馈；若判断有，再由四个分类器分别判断问题类别。判断门槛均为 0.5，因此一条评论可能命中多个类别。

四类分别是：**回答与任务完成、收费与权益、运行体验、界面与广告**。“入门求助”因样本不足，未训练对应分类器。

训练脚本读取已保存的标签，运行时不需要调用大模型、付费 API 或显卡。模型在最终人工测试抽样前冻结，没有用这批人工测试结果重新训练或调参。

## 📊 这份“作业”做得怎么样？

在 180 条人工判定中，2 条不确定，剩余 **178 条**用于计算有无具体反馈的指标。

| 指标 | 本次结果 | 通俗理解 |
| --- | ---: | --- |
| 准确率 | **87.64%** | 178 条中，156 条“有没有具体反馈”的判断与人工一致 |
| 精确率 | **84.31%** | 程序挑出的 102 条中，86 条被人工认可为有具体反馈 |
| 召回率 | **93.48%** | 人工认定的 92 条具体反馈中，程序找到了 86 条 |
| 具体反馈 F1 | **88.66%** | 综合评价“少误报”和“少漏掉”的能力 |
| 四类微平均 F1 | **71.35%** | 汇总四类中可确定的标签判断，评价具体分类表现 |

这不是学习助手的解题正确率，也不是对全部 8.2 万条评论逐条验证后的成绩。

**目前的表现：筛出具体反馈的能力较好，进一步分清问题类型仍有不足。** 例如，运行体验类的 F1 为 47.62%，且人工正例只有 11 条，结果容易受少量错误影响。

模型也会“看词会错意”：实际评测中，一条肯定未订阅时使用体验的评论，仍被判成有问题。提到了“订阅”，并不等于在投诉收费。这样的误报正是本项目需要保留和分析的结果。

完整指标、误报与漏检案例见 [人工评测结果](outputs/human-evaluation-20261030/人工评测结果.md)，原文与逐条判断见 [逐条对照表](outputs/human-evaluation-20261030/逐条对照.csv)。

## 🧭 这个项目能说明什么？

它展示了一条从原始评论、清洗、标注、建模到人工核验的数据分析流程，并提供可追溯的反馈线索。实际用途是辅助人阅读和整理评论，后续仍需要核查问题。

阅读结果时，请保留这些边界：

- **人工评测有提示辅助。** 最终判断由用户作出，AI 提供翻译和候选选项，判定时未展示模型预测；不是完全无提示的独立标注，也没有第二位标注者的一致性结果。
- **样本分数不是总体问题率。** 180 条是按应用、评分分层抽样，不能据此推算全部用户中有多少人遇到了问题。
- **评论是用户自述。** 不能直接当作已经证实的产品故障，也不能证明 AI 提高或降低了学习成绩。
- **没有正式产品排名。** 当前没有完成经核验的全量问题率和改进优先级排名，也未测量实际节省的人工时间。

旧资料里的 **91.61%** 属于早期“评分预测”实验，请勿与本轮反馈识别成绩混用。

## ▶️ 在自己的电脑上复现

在本仓库根目录，按 [完整运行指南](运行指南/换电脑运行指南.md) 准备 Python 3.13 及匹配依赖。Windows 可执行：

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\运行指南\requirements.txt
.\.venv\Scripts\python.exe .\运行指南\复现评测.py
```

也可以双击 `运行指南/一键复现.cmd`。

脚本会把必要文件复制到新的 `复现运行/` 目录，运行冻结模型，逐项比较历史指标，不覆盖归档结果。看到以下提示，表示指标核对通过：

```text
PASS: all metrics match the archived results.
```

依赖版本沿用原实验记录。本次仓库整理与 README 更新未重新安装环境或运行训练评测；部分早期过程脚本含旧机器绝对路径，需按指南调整。复现最终模型结果无需执行这些早期脚本。若要重新训练，请在副本中操作，避免覆盖冻结模型。
