# 评论核验分类规则 v0.1

本规则根据首批 90 条分层样本建立，并对同一批样本回看统一口径。用途是探索分类是否可行，不是独立测试集上的方法验证。标签由助手逐条阅读后给出，尚未经用户或其他人工复核；不得称为人工金标准或据此报告真实分类准确率。

## 核验顺序

1. 先判断评论是否在评价使用体验，区分无关内容、未使用、模糊内容、正向评价和泛泛差评。
2. 有具体问题、限制、改进诉求或入门求助，才记录问题类别；允许多标签。
3. 保留原文证据和中文解释。只标用户表达，不验证其指控的事实真实性，不推断故障的技术根因。
4. 单独记录求助、轻度异议与抱怨／改进请求。所有可处理反馈不等于所有负面体验。
5. 先阅读隐藏评分字段的文本，再合并评分。部分正文自行透露星级，无法完全盲审。

## 五个一级类别与探索性子类

| 一级类别 | 子类代码 | 收录条件 | 排除或保留不确定的情况 |
|---|---|---|---|
| 回答与任务完成 | ANSWER 回答质量 | 明确表示错答、不准确或回答质量差 | “我考试失败”不足以确定模型错答；数据没有标准答案 |
| 回答与任务完成 | EXPLAIN 解释与步骤 | 只给答案、解释难懂、希望增加步骤 | 正面提及解释不算问题 |
| 回答与任务完成 | UNDERSTAND 理解与任务完成 | 不理解需求、无法完成指定任务、不同问题重复回答 | 不据此判定内部记忆机制或长期偏好权重 |
| 收费与权益 | PAY 门槛与额度 | 付费价值不满、次数限制、希望免费、被要求购买 | 仅出现 money 不够；资源内容少不自动算次数限制 |
| 收费与权益 | BILLING 扣费争议与退款 | 明确退款、误购或资金损失诉求 | 用户称诈骗不等于已证实诈骗 |
| 收费与权益 | ENTITLEMENT 已购权益 | 已购订阅不能跨设备使用等 | 未明确原因不直接归为技术故障 |
| 运行体验 | TECH 运行与访问 | 打不开、无法工作、明确报错 | 未指明的功能缺失不推断为故障 |
| 运行体验 | SPEED 响应速度 | 明确慢、等待过久 | “回答立即给出”是正向体验 |
| 界面与广告 | ADS 广告体验 | 广告多、广告影响使用等明确异议 | NO ADS 是赞扬，不算广告问题 |
| 界面与广告 | UI 界面易用性 | 明确界面差或操作问题 | 不把所有不满都归入界面 |
| 入门求助 | ONBOARD 入门与激活 | 不会使用、询问激活码等 | 记录为求助，不能称已验证的系统缺陷 |

子类只用于保留细节。90 条样本不足以训练或评价 11 个独立类别，正式建模先考虑一级类别和“是否存在具体反馈”的识别。

## 无具体问题的状态

- `positive`：正向评价，包括泛泛好评；不代表已经验证真实使用或产品效果。
- `vague_negative`：不满但无法定位具体问题，如 worst app。
- `preuse`：明确仍在下载、刚下载未使用，或仅描述预期效果。
- `irrelevant`：与产品体验无关的内容。
- `ambiguous`：语义不清，不强行赋予问题类别。

## 边界样本

- R017：NO ADS 是正向陈述，不能因 ads 命中而归为问题。
- R051：bad ui 明确支持界面问题；limited resources 的具体含义不明，不添加付费标签。
- R052：四星“很好，但收费”属于轻度收费异议。保守口径可以不算确定抱怨，须报告敏感性。
- R063：五星，但明确用 sadly 描述问题次数有限，是更清晰的高评分问题反馈。
- R037、R075：激活码与新用户操作求助，可以形成帮助文档需求，不归为负面故障。
- R012：不同问题得到相同答案，只支持重复回答现象，不能证明是遗忘上下文。
- R025、R050、R064、R066：功能不全、政策过严、学习结果不好或不符预期，具体原因不明，保留泛泛不满。

正式扩样前应冻结规则版本，人工复核歧义案例。后续用于评估模型的评论应另抽，不与本次制定规则的样本混用。
